# Data Library Filter Architecture

The Data Library filter sidebar is dynamic and asset-type aware.

- Filter visibility is driven by `src/libs/dataLibraryFilterConfig.ts`.
- Query-clause generation and sanitization are centralized in
  `src/components/data_library/filterRegistry.ts`.
- URL parsing/serialization for filters is handled in `src/hooks/useLibraryUrlState.ts`.
- `src/components/data_library/LibraryFilters.tsx` renders from `sections` generated by the registry.

## Important behavior for nested study assets

Tabs that flatten nested arrays from study aggregations (for example, biospecimens, clinical trials,
presentations, and publications) must perform **row-level post-transform filtering** in each asset
definition's `transformResponse` implementation.

Reason: Elasticsearch filters can match at the parent study level, which would otherwise return all nested
rows for that study. Post-transform row predicates ensure only nested rows that actually satisfy the active
filters are shown.

## Change checklist for new Data Library filters

1. Add state/option typing in `src/types/library.ts`.
2. Add filter definition and clause builder in `src/components/data_library/filterRegistry.ts`.
3. Add per-asset visibility in `src/libs/dataLibraryFilterConfig.ts`.
4. Add URL mapping in `src/hooks/useLibraryUrlState.ts`.
5. Add Cypress component tests for:
   - section visibility by asset
   - sanitization of hidden filters
   - query clause generation
   - nested row post-transform filtering for affected assets
